# 验证记录

## 当前默认：机械臂启动姿态移入限位内部（2026-09-09）

此前无回退小跑在 7.96 秒锁存停止。进一步诊断发现，WBT 的机械臂零位将
joint2 放在下限、joint3 放在上限。原模型采用
`dq[i+1] = dq[i] + v[i] * dt[i]`，因此第一个预测关节位置由测量确定，
不能靠当前加速度修正。在一个记录状态回放样本中，joint3 的位置为
0.00037866 rad、速度为 0.05170632 rad/s，20 ms 后必然为 0.00141278 rad，
超过其 0 rad 上限且超过 1e-3 的解验收阈值。
[诊断与启动目标检查](interior-pose-diagnosis.json) 保存了该数值证据。
该样本说明存在不可行输入，不代表已将历史每次失败都归因为同一条约束。

修复：腿仍从原 WBT 零位启动，机械臂肩肘目标改为 joint2=0.15 rad、
joint3=-0.30 rad。解释执行版本用实际落地姿态构建参考；编译版本先运动到库元数据
中的关节参考，再以相同参考建立 MPC。启动目标检查了维度、有限值和关节限位。
记录新参考到 `deployment_nominal.json`，完整重建 `.cache/deployed` 的三个 C 文件、
共享库和元数据。GCC -O0 编译 138.35 秒，导出时求解器、解码和约束检查通过
1e-7 数值等价性验证。没有恢复 IPOPT，没有放宽限位/验收，没有改动原 OCP 方程，
没有采用诊断中尝试的迭代数/障碍参数/热启动改动；保持 10 ms/80 ms 调度。

[解释执行验证](interior-pose-interpreted.json)：15 秒小跑，163 次求解全部成功，
0 次故障，完整调用 p95 157.4 ms。

[默认编译入口验证](interior-pose-compiled-trot.json)：30 秒隔离平地小跑，
351 次调用全部由 Fatrop 成功完成，0 次保持故障、0 次回退，全程力矩控制。
两组对角触地交替通过，腿关节最大峰峰位移 0.18806 rad；基座高度
0.32090～0.32881 m，最大 roll/pitch 0.008963 rad。
完整调用平均 91.3 ms、p95 111.0 ms、最大 172.1 ms；307/351 次超过 80 ms，
所以只宣称本次闭环运行通过，不宣称墙钟实时或达到论文 80 Hz。
测试使用原 Robot 和 WorldInfo，地面为隔离平地；未验收前进、转向、复杂地形或长期运行。

[编译版机械臂验证](interior-pose-compiled-arm.json)：6 秒站立/末端上升测试，
50 次 Fatrop 调用全部成功、零故障，全程力矩控制，调用间隔为 80 ms。
末端实际上升 9.523 mm，Pinocchio 与 Webots 实际末端高度最大差 0.06345 mm；
完整调用 p95 73.8 ms，1/50 次超过 80 ms。本次测试通过。
更新后需重置 Webots 世界并重启控制器，使新的位置启动与共享库参考一起生效。

## 实时性和范围

以上运行是同步在线闭环：每次把物理测量送入原版 OCP，执行首区间力矩。
求解期间 Webots 等待，因此目前没有达到 15 ms 墙钟实时要求。
编译、线程隔离与降低模型复杂度可作为后续性能工作，不能用仿真时间周期
代替墙钟性能验证。

五模型都已做离线数值检查，物理闭环主要验收默认 RNEA/Fatrop。
未验证所有模型/求解器组合、walk、转向、大幅末端运动、非零末端接触力、
6 自由度机械臂、长时间运行，以及原世界石块和窄桥上的越障。
原算法没有地形/碰撞/冲击约束，不能据平地结果宣称越障或真机可用。
